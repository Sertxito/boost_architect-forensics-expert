A comprehensive **GitHub Copilot boost** that transforms Copilot into an autonomous forensics engine for:

- ✅ **Reconstructing unknown systems** from code, config, and deployment evidence
- ✅ **Auditing legacy platforms** for risk, value, and evolution paths
- ✅ **Assessing cloud architecture** for security, reliability, and cost
- ✅ **Quantifying technical debt** across all categories
- ✅ **Designing modernization strategies** with phased, evidence-based roadmaps
- ✅ **Producing formal findings** with business impact and strategic recommendations
- ✅ **Making final go/no-go decisions** using KEEP | REFACTOR | MODERNIZE | REPLATFORM | REBUILD taxonomy

## Quick Start

### 1. Clone the Repository

```bash
git clone https://github.com/Sertxito/boost_architect-forensics-expert.git
cd boost_architect-forensics-expert
```

### 2. Load as GitHub Copilot Boost

Open GitHub Copilot in VS Code and load this repository as a boost (awesome-copilot framework).

### 3. Invoke the Main Agent

```
@Architect Forensics - analyze this platform
```

Copilot will coordinate all 10 specialist agents to produce a comprehensive audit.

## Core Concepts

### 🎯 Finding Model (9 Fields)

Every finding is structured with:

1. **Evidence** — Concrete file, config, metric, architectural clue
2. **Root Cause** — Why it exists (not just what's visible)
3. **Business Impact** — Consequence for delivery, cost, compliance, UX
4. **Technical Impact** — Consequence for maintainability, scalability, reliability, security
5. **Risk** — Critical | High | Medium | Low
6. **Recommendation** — Specific action (not generic advice)
7. **Estimated Effort** — S / M / L / XL
8. **Expected Value** — What improves after acting
9. **Priority** — P0 / P1 / P2 / P3

### 🎭 Decision Taxonomy

Final decisions use a proven taxonomy:

| Decision | Meaning |
|----------|---------|
| **KEEP** | No architectural change; maintain current path |
| **REFACTOR** | Improve internal quality without changing boundaries |
| **MODERNIZE** | Evolve stack within existing architecture |
| **REPLATFORM** | Change underlying platform (e.g., VM → Containers) |
| **REBUILD** | Start fresh with lessons learned |

## Philosophy

### The 4 Core Rules

1. **Reconstruct, don't explain** — Go deep into system architecture
2. **Recommend smallest moves** — Not fashionable technology
3. **Decide as architect** — Evidence-based, not "it depends"
4. **Answer the final question** — **If this were my platform and my budget, what would I do tomorrow morning?**
